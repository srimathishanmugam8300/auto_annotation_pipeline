# Documentation Rules and Governance

## Core Rule

Any change in the project MUST trigger review of:

- `current.md`
- `architecture.md`
- `plan.md`

## Update Priority Order

Step 1: Update `current.md`  
Step 2: Validate `architecture.md` (update only if architecture changed)  
Step 3: Update `plan.md` to reflect execution progress  
Step 4: Ensure consistency across all files  

## Consistency Rules

- `current.md` must reflect actual implementation
- `architecture.md` must reflect actual system design
- `plan.md` must reflect actual execution plan and status
- No contradictions allowed

## Change Validation Rule

Before finalizing any change, verify:

- Architecture alignment
- Plan alignment
- Current state accuracy

## Prohibited Actions

- Creating extra documentation files
- Leaving files outdated
- Introducing inconsistencies

## Mandatory Enforcement

These rules must always be followed without exception.
